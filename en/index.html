Demos are easy. Keeping going is hard.

Build long enough by chatting with AI, and this happens

  1. 01

    Sessions pile up

    “Continue from yesterday”, “New chat”, “Keep going”… hundreds of sessions, and no telling which belongs to what.

  2. 02

    History and decisions get lost

    Why something changed and who decided lives in some old chat — weeks later, you can't find it.

  3. 03

    New changes break old features

    Every session focuses on the task at hand. Nobody checks whether what already worked still does.

How RelayForge fixes it

Continuous integration for AI development

A branch per requirement

Each new requirement gets its own branch, worktree and sessions. Sessions are filed under their requirement, stay alive when you switch, and never collide.

Only accepted work merges

You check each item and click “Confirm done” — only then does the change merge. Every commit is tagged with its requirement and session, so you can always trace it back.

A test suite that grows and reruns

AI writes test sets from your acceptance checks. They stay with the project, and one click reruns the whole suite after a change. When a feature is replaced, its tests are marked stale automatically.

Bugs flow back, get fixed, get retested

Problems found in testing or use become an issue that AI triages first. Click “Start fix” and Claude Code or Codex fixes it on its own branch, then hands back a report for you to confirm.

AI sets up the test environment

AI reads the project and proposes how to start it. Once you approve, launch services and watch logs inside the app — and turn anything wrong into an issue, logs included.

Progress, decisions and the map, on record

AI records its plan, progress and every change of direction. The product map holds only accepted work, so it always matches main.

Bring the AI you already use

Plugs into Claude Code and Codex — no new AI subscription

RelayForge has no model of its own and needs no extra AI credits. It runs the Claude Code or Codex you've already installed and signed in to, on your own account and plan.

Claude CodeCodex

    Each build session is the same CLI you know, embedded right next to the requirement.

  • Pick the tool and model per session

    Choose Claude Code or Codex as the default in Settings, and pick the tool and model again when you start a fix.

    Background triage and summaries run through the same tool you chose — no other model service involved.

Round after round

Every requirement goes through the same loop

  1. 01

    Scope

    AI talks but doesn't edit: one question at a time, it pins down the spec, the features it touches and the acceptance checks, with mockups when needed.

  2. 02

    Build and test

    Once you approve, AI writes the code on the requirement's own branch and logs progress. In the test stage, a test session writes and runs tests from your acceptance checks and sends problems back to development.

  3. 03

    Accept and merge

    Run the app inside RelayForge and try each item yourself. The change merges into main only when you confirm.

  4. 04

    Update the map, start the next round

    Accepted changes go into the product map. The next requirement starts from the latest main, with the old tests still on guard.

Before you start

  • A Mac
  • Claude Code or Codex CLI, installed and signed in
  • Git, with your project as a repository that has at least one commit

Your code stays on your Mac

RelayForge runs locally and model calls go through your own Claude Code or Codex account. Merges happen only in your local repository; nothing is pushed until you click Publish. It never reads secrets, .env files or Git-ignored files.

It opens on the FlowNote demo project first; browsing the demo never calls a model.
