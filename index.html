    会话越堆越多

  2. 02

    历史和决定找不到

    当时为什么这么改、谁拍的板，只存在某段聊天里，过几周就翻不到了。

  3. 03

    改了新的，旧的又坏

    每次只盯着眼前这个需求，以前做好的功能有没有被改坏，没人知道。

RelayForge 怎么解决

把 AI 开发变成持续集成

每个需求一条分支

新建需求就开出它自己的分支、工作目录和会话。会话按需求归档，切换需求时不会断，改动互不干扰。

验收通过，才合进主线

你按清单逐条验收、点「确认完成」，改动才合并。每个提交都标着来自哪个需求、哪次会话，随时能追回去。

测试越攒越多，整套重跑

AI 按验收条件写测试集，测试跟着项目一直攒着，改动后一键整套跑一遍。功能被替代时，相关测试自动标成过期。

问题回流，修好再测

测试和使用中发现的问题记成一条，AI 先初判；你点「开始修复」，Claude Code 或 Codex 在独立分支修好，交回报告等你确认。

测试环境，AI 来搭

AI 读完项目给出启动方式，你同意后在软件里启动服务、看日志；发现不对，连同日志直接记成问题。

进度、决定和大图，都有据可查

AI 边做边记计划、进度和方向调整。产品大图只记录验收过的内容，始终等于主线上的产品。

用你已经在用的 AI

无缝接入 Claude Code 和 Codex，不用再订阅新的 AI 套餐

RelayForge 不自带模型，也不用另买 AI 额度。它直接调用你电脑上已经安装并登录的 Claude Code 或 Codex，用的是你自己的账号和套餐。

Claude CodeCodex

  • 原样嵌入

    开发会话就是你熟悉的那个命令行界面，嵌在需求旁边，用法不变。

  • 按会话选工具和模型

    设置里选默认用 Claude Code 还是 Codex；开始修复时也能单独挑工具和模型。

  • 没有新的 AI 账单

    后台的初判、总结也走你选的那个工具，不另外接别的模型服务。

一圈一圈，持续迭代

每个需求都走完同一个闭环

  1. 01

    立项

    AI 只聊不改：一次问一个问题，把需求说明、要改的功能点和验收条件写清楚，必要时出设计稿。

  2. 02

    开发和测试

    你放行之后，AI 在需求自己的分支里写代码、记进展；进入测试阶段，测试会话按验收条件写测试、跑测试，有问题交回开发。

  3. 03

    验收和合并

    在软件里把程序跑起来，按清单亲手试一遍。你确认完成，改动才合进主线。

  4. 04

    更新大图，开始下一轮

    验收过的变化写进产品大图。下一个需求从最新的主线开始，旧功能的测试继续守着。

代码留在你的电脑上

RelayForge 在本地运行，模型调用走你自己的 Claude Code 或 Codex 账号。合并只发生在你本地的仓库里，推送到远端只在你点「发布」时进行。读代码时不读密钥、.env 和被 Git 忽略的文件。

首次打开会进入 FlowNote 演示项目，浏览示例不会调用模型。
